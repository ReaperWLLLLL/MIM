# Whole-chapter production

Read the chapter boundaries and all substantive subsections before choosing the opening. A short highlight is not a whole chapter.

Use the [design conversation](creative-first.md#design-the-explanation) to agree on the main example's scale, features and simplifications before production. A chapter coverage table is not a substitute for that agreement. Reuse prior answers about style, but settle content choices that the new chapter introduces.

## Coverage without slide copying

Keep a compact source-to-sequence table: page range, concept, visual action, and depth (worked / explained / deferred). Group repeated proof slides into one reasoning sequence; split a dense slide if needed. Preserve prerequisites but reorganize repetitions around an explanatory example. Disclose omitted exercises or specialist derivations and unresolved source errors.

Estimate duration from conceptual load. Reuse an agreed duration; otherwise state a working budget and proceed if it does not materially narrow the task. If the time limit cannot cover the scope, ask about that tradeoff rather than silently dropping the latter half.

## Continuity across sections

Follow the agreed main example while useful. Carry node names, colors, reference directions and quantities forward. A small starter may isolate an operation; reapply it to the main example so the learner sees its interactions. Retain or re-establish the next argument's required state. Use a separate example where the main one cannot exhibit coupling or degeneracy. A simpler example that removes an agreed structural feature is a design change to discuss, not a layout optimization.

Use native scene classes at useful revision boundaries, not one class per source page. Keep an ordered list of classes/clips in rebuild notes. Render into a fresh build directory; concatenate compatible silent clips and verify the continuous output, not only the clips.

## Proportionate review

Inspect one demanding sequence early. At completion inspect each section's meaningful state plus crowded transitions. Check numerical claims independently, inspect actual size/fps/duration and fully decode the output. A coverage table documents scope, not teaching quality. Give humans the continuous video and a few specific review questions, not a pile of compulsory audit paperwork.
