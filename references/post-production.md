# Optional post-production

Load for requested audio, presentation packaging or publication. Keep native silent clips as the visual master.

## Narration and sound

Write speech against established visual beats. Edit phrasing to fit useful pauses before changing an accepted animation. Use installed Humanizer editors while preserving terminology; keep pronunciation substitutions separate. Scientific talks generally need restrained delivery. Music and event effects are separate opt-ins.

Use the backend, host and authorized voice specified by the user/project. Private SSH aliases and voices are configuration, not universal Skill policy. Inspect existing setup before installing or downloading. Do not fall back from a requested remote host to local models or another service without authorization. Label synthetic voices appropriately.

Existing strict v0.2 builds use [research-video.md](research-video.md); its remote-only voice implementation, timing and provenance contracts still apply. If these conflict with a new request, explain the incompatibility or use a separate agreed native route instead of pretending strict validation passed.

## PPT, HTML and PDF

Export requested formats only. Video-based PPT uses silent section clips, useful posters and notes, not native-editable Manim objects. PDF contains selected still states. Existing v0.1 decks retain [output-contract.md](output-contract.md). Do not migrate an accepted animation solely for an unused exporter.

Verify media/package structure separately from actual target-application playback. Report untested items. Consult [licensing-and-publication.md](licensing-and-publication.md) before distributing source documents, fonts, voices or models. Publishing/pushing require separate authorization.
